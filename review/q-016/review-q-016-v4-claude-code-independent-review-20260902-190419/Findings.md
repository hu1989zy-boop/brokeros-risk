## F1 — BLOCKING — dependency conflict prevented `flutter pub get`

**Symptom (raw):**
```
Because freezed >=3.2.5 <3.2.6-dev.1 depends on analyzer >=9.0.0 <11.0.0 and
build_runner >=2.15.2 depends on analyzer >=13.3.0 <15.0.0, freezed >=3.2.5
<3.2.6-dev.1 is incompatible with build_runner >=2.15.2.
So, because brokeros_risk_console depends on both freezed 3.2.5 and
build_runner 2.16.0, version solving failed.
```
The pinned `build_runner: 2.16.0` requires `analyzer >=13.3.0`; the pinned
`freezed: 3.2.5` requires `analyzer <11.0.0`. No solution exists, so
`flutter pub get` fails and **nothing downstream can run** (no codegen, no
analyze, no test, no build).

**Fix:** `frontend/pubspec.yaml` — `build_runner: 2.16.0` → `build_runner: 2.15.1`
(the highest build_runner still compatible with analyzer <11, per pub's own
resolution). `freezed` left at 3.2.5.

**Verified:** `flutter pub get` and `dart run build_runner build
--delete-conflicting-outputs` both succeed (log 02, `PUBGET_OK` / `BUILDRUNNER_OK`).

## F2 — BLOCKING — `RiskCaseListPage` name collision → 15 compile errors

**Root cause:** the identifier `RiskCaseListPage` was defined **twice**:
- `lib/features/riskcase/data/risk_case_models.dart` — a Freezed **data model**
  (a page of results: `items`, `page`, `pageSize`, `hasNext`);
- `lib/features/riskcase/presentation/risk_case_list_page.dart` — the **screen
  widget** (`class RiskCaseListPage extends ConsumerStatefulWidget`).

Because the presentation file imports the data library, both definitions are in
scope; the local widget shadows the data class, so every use of the model's
getters resolves against the widget. Result (log 01): 15 analyzer errors —
`undefined_getter` for `items`/`page`/`hasNext`, `ambiguous_import`, and
`argument_type_not_assignable` across the list page and two test files. The app
**does not compile**.

**Fix (rename the data model; keep the idiomatic Flutter widget name):**
- `risk_case_models.dart`: `RiskCaseListPage` → `RiskCaseSummaryPage` (a page of
  `RiskCaseSummary`; also mirrors the backend `RiskCasePage`). Freezed part
  references (`_$…`, `_…`, `_$…FromJson`) renamed with it.
- Data-model consumers updated: `data/risk_case_repository.dart`,
  `application/risk_case_notifiers.dart`, `presentation/risk_case_list_page.dart`
  (only the `AsyncValue<…>` type use — the widget class and its State are
  unchanged), and tests `risk_case_notifiers_test.dart`,
  `risk_case_widgets_test.dart`, `api_contract_test.dart`,
  `test/support/fake_risk_case_repository.dart`.
- `lib/app/app_router.dart` and the widget class in
  `presentation/risk_case_list_page.dart` were **left untouched** (they legitimately
  name the screen widget `RiskCaseListPage`).
- `risk_case_models.g.dart` / `risk_case_models.freezed.dart` regenerated by
  build_runner for the new name (not hand-edited).

**Verified:** all 15 collision errors are gone; see F-final below.

## F3 — MINOR (test) — `AsyncValue.hasError` does not exist in flutter_riverpod 3.4.2

**Symptom (raw, both `flutter analyze` and `--platform chrome` compile):**
```
error • The getter 'hasError' isn't defined for the type
'AsyncValue<RiskCaseSummaryPage>' • test/risk_case_notifiers_test.dart:29:29
```
The pinned `flutter_riverpod: 3.4.2` `AsyncValue` exposes `error` but not
`hasError`. This is a real compile error in a delivered test.

**Fix (test file only, §16.5-A):** `risk_case_notifiers_test.dart:29`
`expect(notifier.state.hasError, isTrue);` → `expect(notifier.state.error,
isNotNull);` — using the supported getter, and preserving a distinct assertion
from the following `expect(notifier.state.error, same(unavailable));`.

## Infra regression (carried, fixed earlier this review) — Keycloak `${VAR:?}` broke compose

Codex's new `keycloak` service in `docker-compose.yml` uses
`${KEYCLOAK_ADMIN_PASSWORD:?…}` / `${KEYCLOAK_OPERATOR_PASSWORD:?…}`
(required-with-error). `docker compose … config` interpolates **all** services
regardless of `--profile`, so the schema-agnostic `scripts/verify-infrastructure.sh`
(which runs `compose config`) began failing with "required variable … is missing a
value." Fix: `verify-infrastructure.sh` exports harmless placeholder values for
those two variables (it never starts Keycloak), keeping the `:?` production safety
intact. Verified: `docker compose --profile app config` succeeds.

## False alarm — ruled out (NOT a defect)

An intermediate `flutter test` run (default **VM** platform) reported that
`dart:js_interop` / `package:web` are "not available on this platform," pulled in
through `browser_pkce_authenticator.dart`. This is **not** a product defect: this
is a web-only application, and its tests must run on `flutter test --platform
chrome`, where those libraries are available. Re-running on the chrome platform
made every one of those errors disappear (only F3 remained, then was fixed). I am
recording this explicitly so it is not mistaken for an open issue: the web-only
auth code is fine; my initial VM test invocation was the wrong platform.
